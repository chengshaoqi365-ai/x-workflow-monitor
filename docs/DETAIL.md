# X 自动化工作流监控

在 DSH **左侧栏**注册 **X 工作流** 入口，点击打开完整页面。页面以 **运行详情 + 待办队列** 为主：首屏回答“是否在跑、第几轮 / 第几个、上次为什么结束、哪里失败、今天做了多少、账号是否安全”，原始日志和发现池降为可折叠的次级内容。

## 首屏

1. **运行头（不滚动）**
   - 标题 `X 自动化工作流` + `@账号`
   - 状态 pill：运行中 / 已完成 / 已停止 / 失败 / 未运行 / 控制服务未连接
   - 第二行：本次第 x/y 轮 · 17/30 · 已运行 12:34 · 预计剩余 8 分钟（或上次运行摘要）
   - 右侧：运行设置、开始运行、dry-run、停止

2. **进度条（sticky）**
   - `17/30` 进度条
   - 当前 `@handle` 与阶段（搜索 / 悬停 / 关注 / 点赞 / 回复 / 休息）
   - 关注 / 点赞 / 回复 / 失败 / 跳过计数
   - 最后一条人类可读事件（失败时显示具体原因）

3. **主内容两栏**
   - 左：本轮目标表。列 `# / 账号 / 关注 / 点赞 / 回复 / 结果 / 时间`；默认最近 10 行，`查看全部` 打开抽屉（最多 30 行）；失败行红色；点行展开推文摘要、回复原文、失败详情、尝试次数、时间
   - 右：需要处理（只读）、本次运行（模式 / 计划轮数 / 开始 / 结束 / 耗时 / 退出码 / 停止原因）、安全与节奏（浏览器 / 平台告警 / 出口 / 账号时区 / 今日计数）

## P1 / P2

- **P1（滚动可见）**：运行历史（最近 10 次真实运行，不含 dry-run）、回复审计（时间 / 账号 / 回复原文 / 字数 / 状态）
- **P2（默认折叠）**：原始日志（自动跟随、只看错误、搜索、下载）、发现池 / 候选人池、运行设置

## 运行控制

「运行设置」弹层通过本机控制服务操作 connect 流程：

| 操作 | 请求 |
| --- | --- |
| 读取状态（每 2 秒） | `GET http://127.0.0.1:8788/control/status` |
| 开始运行 | `POST http://127.0.0.1:8788/control/run` `{rounds, max_checks: 30, max_new_follows, dry_run: false}` |
| dry-run | 同上，`dry_run: true`（只读取页面，不点击，不写入运行历史） |
| 停止 | `POST http://127.0.0.1:8788/control/stop` `{}` |

- 轮数：1–10，默认 3；每轮固定 30 个 id
- 本次新关注数量：0–100，0 表示不限制
- 运行中「开始运行」「dry-run」禁用，「停止」可用；结束后恢复
- 控制服务未启动时首屏显示明确提示；409 `already_running` 显示「已有任务在运行」；启动失败显示服务返回的 `error` / `message`

## 数据接口

页面优先读取以下只读接口（契约见 `docs/24-插件UI优化任务书.md` §4）：

- `GET http://127.0.0.1:8787/status/v2`：运行快照、计数、今日、安全、待处理数量、最后事件
- `GET http://127.0.0.1:8787/actions?run_id=&status=&limit=100&before_id=`：逐目标动作明细
- `GET http://127.0.0.1:8787/runs?limit=20`：运行历史（不含 dry-run）
- `GET http://127.0.0.1:8787/pending?limit=100`：失败 / 已关注未回复待处理项

接口未上线时自动回退到 `GET /status` + `GET /control/status`：缺失字段显示“暂无 / 未接入”，不伪造数字；回退模式下目标表从运行日志推断可确认的信息（只显示能确认的动作结果）。

## 服务管理

运行头下方分别显示状态服务（8787）和控制服务（8788）的连接状态。任一服务离线时可在这里启动，服务就绪后页面自动刷新。DSH Host 调用固定脚本启动 HTTP 服务，启动失败时页面显示具体错误。

也可以在终端手动启动：

```bash
cd x-desktop-auto
bash scripts/start_status_server.sh
bash scripts/start_control_server.sh
```
